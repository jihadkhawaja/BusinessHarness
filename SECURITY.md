# Security model

The runner treats PR content, filenames and external reference text as untrusted data. Review requests contain only bounded, redacted diffs and reference documents resolved through trusted routing policy. Models receive no tools, command execution, filesystem access, write tokens, or ability to fetch URLs. No repository scripts, AGENTS.md instructions, hooks, builds or tests are executed during review. Provider API endpoints are fixed; Jira accepts only an HTTPS atlassian.net tenant. Other reference and host endpoints come from trusted configuration; captured identifiers are URL encoded and cannot change the destination. Restrict runner egress to approved services, including DNS-resolved addresses; endpoint validation is not a network sandbox. HTTP redirects are refused and TLS validation remains enabled.

Git arguments use `ProcessStartInfo.ArgumentList`, without a shell. Refs resolve to commit IDs before comparison. Filename pathspecs are literal. External diff drivers, text conversion and filesystem monitoring are disabled; Git receives an allowlist of process environment variables rather than API secrets. Global/system Git configuration is disabled. **Git metadata and the installed Git binary must come from a trusted CI checkout**, not an uploaded attacker-created `.git` directory.

Credentials come from secret environment variables. Known runtime tokens, common token patterns and credential assignments are redacted before provider submission; complete and truncated private-key blocks are masked. Sensitive filenames are withheld and reported. This is a heuristic safety measure, not comprehensive secret detection: encoded, novel, fragmented or arbitrary confidential data may not match. The offline scan covers added lines in the selected diff, not all history or all repository content. Use a dedicated secret scanner and rotate exposed credentials.

`review` sends source-code context, PR/MR metadata and resolved references to the selected external API. Approve this data flow for your organization and configure its retention requirements; OpenAI requests set `store=false`, which is not a universal zero-retention guarantee. Redaction does not make arbitrary proprietary code public-safe. `scan` makes no provider, host or reference HTTP calls. Optional host feedback is deterministic application logic, enabled only by `--feedback comment` or `--feedback auto`. Host credentials never enter model input. The harness checks the source SHA and host base before review, rechecks metadata before publication and binds approvals to the reviewed commit. Draft requests and reviews with withheld files are not automatically approved. Host writes are not retried automatically; feedback failures return a nonzero code. GitLab gate failures remove only the caller’s own approval and publish a note; configure required passing CI checks to block merging.

Prompt separation, schema constraints and finding validation reduce the effects of prompt injection; they do not prove that a model's judgment is correct. Local findings cannot be removed by model output. Missing/partial/unverifiable reference assessments fail the gate. Size limits, refusals and incomplete responses stop the run. AI review supplements code review, tests, SAST and policy controls.

Review skills are explicit trusted policy, with a bounded bank and an allowlisted
per-invocation selection. Only selected, redacted guidance enters provider system
instructions, subordinate to the built-in review rules. PR files, metadata,
references, comments and memory cannot define or enable skills. The runtime does
not discover `SKILL.md` files, execute skill scripts, download skill resources or
grant tools. Protect bank definitions and pipeline selection alongside other
policy; skills do not change validation, gates, or feedback authorization.

Pipeline guidance:

- Pin runner/action/image artifacts to reviewed commits/digests. Never build this runner from the PR being reviewed while supplying API secrets.
- Keep policy and secret-bearing pipeline definitions trusted. Protect workflows/templates with branch protection and ownership reviews. A same-repository check alone does not make all branch content trusted.
- Require environment approval before exposing API secrets to contributor-controlled workflows. Leave fork secret protections enabled; run credential-free scans separately on untrusted contributions.
- Use read-only checkout credentials, fresh isolated runners and narrow network egress. Avoid sharing self-hosted agents or mounting Docker sockets into review containers.
- Mount reviewed code read-only and reports separately. The image defaults to non-root; drop capabilities, forbid privilege escalation and use a read-only root filesystem.
- Use dedicated output directories outside the checkout where possible. Link components are rejected, but a hostile process sharing the runner can still race filesystem operations. Isolate jobs rather than treating path checks as an OS sandbox.
- Reports may contain sensitive business context even after token redaction. Restrict artifact access and retention. Markdown escapes untrusted HTML, links and mentions.
- Comment templates are explicit trusted policy or runner-managed Markdown, never discovered from reviewed content. Literal template markup is trusted; inserted review values stay escaped and redacted. Required sections and input/output limits apply to custom templates. Templates cannot execute code or change feedback decisions.

The build audits direct and transitive NuGet dependencies at low severity, treats audit warnings as errors, restricts package sources to nuget.org, and uses committed lock files. Dependabot proposes dependency, action and container updates; review and test updates before merging. SDK and runtime patch pins require periodic maintenance too. Stable GitHub Releases trigger NuGet publication through `publish-nuget.yml`: the tag must match the package version and identify a commit on `main`. Verification and offline smoke checks run without publishing credentials. A separate job downloads that run's package and obtains a short-lived NuGet credential through OIDC in the tag-restricted `nuget` environment; it does not check out or build source. Restrict the NuGet Trusted Publishing policy to this repository, workflow, environment and the `BusinessHarness` package. Protect release creation, tags, workflows and environment configuration as trusted maintainer operations.

For a security issue, contact repository maintainers privately through the hosting platform's security reporting channel before opening a public issue. Never include real tokens or proprietary diff content in reports.

Long-term memory is disabled by default. Enabling it persists redacted historical review context in trusted storage outside the reviewed checkout. Namespace/repository/session partitions limit recall; broader scopes must be explicitly requested. Follow-up ingestion requires authenticated event provenance from the receiver, an actor allowlist and a matching configured agent mention. The CLI does not authenticate arbitrary public webhook bodies. Event data cannot choose policy, endpoints, namespace, storage or write scope. Corrupt snapshots stop review without overwriting existing memory. Recalled text is untrusted context and cannot authorize approval, remove local findings or satisfy current requirements without current diff evidence. Storage is unencrypted business data: protect local permissions, volume mounts and backups. See [memory operation](docs/memory.md) for retention, bounds and deployment limits.
